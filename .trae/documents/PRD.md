# 跨校区教室借用审批与设备归还核验系统 - 产品需求文档

## 1. 产品概述

一个完整的跨校区教室借用审批与设备归还核验管理系统，支持从借用申请、审批排期、设备交接到归还核验的完整流程。系统预置多种业务场景样本，支持时间冲突检测与替代教室推荐，提供多维度统计报表。

**核心价值**：简化跨校区教室资源调度，减少设备丢失，提升后勤管理效率。

**目标用户**：
- 教职员工（借用申请人）
- 校区管理员（审批排期）
- 设备管理员（设备交接）
- 后勤人员（归还核验）

## 3. 核心流程

### 3.1 主流程：教室借用与归还

```
借用申请 → 校区管理员审批 → 审批通过 → 设备管理员交接设备 → 使用中 → 归还核验 → 完成
                    ↓
              时间冲突? 
                ↓是
           显示可选替代教室 → 重新选择或取消
```

### 3.2 时间冲突检测流程

当申请人选择教室和时间段时，系统实时检测：
1. 查询该教室在选定时间段是否已有审批通过的借用记录
2. 若有冲突，阻断提交，提示冲突信息
3. 自动查询并推荐同校区可用教室列表

### 3.3 设备归还核验流程

1. 设备管理员生成归还清单
2. 后勤复核员逐项核验设备数量和状态
3. 进行清洁检查（拍照上传）
4. 若异常（设备遗失、清洁不合格），记录异常原因
5. 完成归还，更新教室和设备状态

### 3.4 预置样本场景

| 场景ID | 场景名称 | 状态 | 异常类型 |
|--------|----------|------|----------|
| S001 | 正常借用与归还 | 已完成 | 无 |
| S002 | 设备遗失 | 已完成 | 设备遗失 |
| S003 | 时间冲突阻断 | 已取消 | 时间冲突 |
| S004 | 清洁不合格 | 已完成 | 清洁不合格 |
| S005 | 多校区借用 | 使用中 | 无 |

## 4. 数据模型

### 4.1 核心实体

- **Campus（校区）**：id, name, location
- **Classroom（教室）**：id, name, campusId, type（普通/多媒体/实验室）, capacity, equipmentList
- **BorrowApplication（借用申请）**：id, classroomId, applicantId, startTime, endTime, purpose, status, createdAt
- **Equipment（设备）**：id, name, classroomId, status, quantity
- **EquipmentHandover（设备交接）**：id, applicationId, equipmentId, quantity, handoverTime, handlerId
- **ReturnVerification（归还核验）**：id, applicationId, equipmentCheck, cleaningStatus, cleaningPhoto, abnormalReason, verifierId, verifiedAt
- **ApplicationHistory（申请历史）**：id, applicationId, action, actorId, timestamp, note

### 4.2 申请状态流转

```
PENDING（待审批）→ APPROVED（已审批）→ EQUIPMENT_HANDED（设备已交接）→ IN_USE（使用中）→ RETURN_PENDING（待归还）→ COMPLETED（已完成）
                          ↓
                   REJECTED（已拒绝）
```

## 5. 技术选型

- **前端框架**：Remix + React + TypeScript
- **样式方案**：Tailwind CSS + 自定义CSS变量
- **数据库**：SQLite（通过 Prisma ORM）
- **数据初始化**：Prisma Seed 脚本预置样本数据
- **路由方案**：Remix File-based Routing

## 6. 验收标准

### 6.1 功能验收

- [ ] 用户可提交借用申请，选择校区、教室、时间段、设备
- [ ] 校区管理员可审批申请，时间冲突时阻断并显示替代教室
- [ ] 设备管理员可进行设备交接确认
- [ ] 后勤可进行归还核验，支持异常登记和清洁检查
- [ ] 详情页完整展示所有信息，包括历史节点
- [ ] 统计页支持按校区、教室类型、异常原因聚合
- [ ] 预置5个样本数据，包含4种异常场景

### 6.2 数据验收

- [ ] 正常归还场景：完整流程，所有状态正确
- [ ] 设备遗失场景：异常原因正确记录
- [ ] 时间冲突场景：申请被阻断，替代教室显示
- [ ] 清洁不合格场景：清洁状态为不合格
